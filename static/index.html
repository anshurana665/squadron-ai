Architecture

Three Agents.
One Mission: Zero Vulnerabilities.

A LangGraph-powered stateful pipeline where specialized agents collaborate and self-correct until the EVPC score hits 1.0.

🏛️
Agent 01
Manager Agent
The Architect
Performs rigorous static pre-scans to detect CWE patterns — SQL injection, command injection, path traversal, and hardcoded secrets — before a single LLM call is made. Forces output of a surgical 5-step JSON execution plan.
Static Analysis · CWE Tagging · Task Decomp
→
⚙️
Agent 02
Developer Agent
The Engineer
Operates with strict Enterprise Ruleset and temperature=0.15 for maximum determinism. Accepts the JSON plan and generates raw, parameterized, secure code. No fluff. No hallucinated libraries. Pure functional patches.
Patch Generation · temp=0.15 · Enterprise Rules
→
🛡️
Agent 03
Reviewer Agent
The Gatekeeper
Executes patched code inside an ephemeral E2B sandbox. Analyzes runtime logs, exit codes, and stack traces. If EVPC < 1.0, the trace is attached and routed back to the Manager. Only a perfect score ships.
E2B Sandbox · EVPC Scoring · Self-Correction
🔁
Self-Correcting EVPC Loop
If the Reviewer's EVPC score is below 1.0, the failure trace is sent back to the Manager for iterative re-patching — the cycle repeats until execution is verified.
Execution-Verified Patch Correctness

Security Audit · v4.0

Squadron Audits Itself
Before Auditing You.

The platform that scans your code has passed its own rigorous production-grade security review.

✅
CWE-22 · Path Traversal
File Upload Validation
Implemented os.path.basename and realpath validation on all file upload endpoints to prevent directory escape attacks.
✅
CWE-78 · Command Injection
Sandbox Shell Hardening
shlex.quote() applied to all shell execution arguments inside the E2B sandbox integration layer.
✅
CWE-400 · Memory Exhaustion
DoS Prevention via TTL
TTL-based job eviction with a 1-hour window prevents unbounded memory growth and protects against resource exhaustion attacks.
✅
CWE-116 · Stored XSS
Dynamic HTML Sanitization
html.escape() applied to all dynamic UI elements in Streamlit to prevent stored cross-site scripting via code snippets.
✅
CWE-200 · Information Exposure
Error Message Sanitization
All API error messages sanitized to strip stack traces and internal paths. Production errors return generic codes only.
✅
CWE-693 · CORS Policy
Hardened Cross-Origin Policy
CORS restricted to trusted localhost and explicit production origins — no wildcard allow-all policies in staging or production.
